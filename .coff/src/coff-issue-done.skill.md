## 手順

1. `.claude/skills/coff-detail-issue/SKILL.md` の状態仕様と done の出口基準を把握する。 <!-- skill は自動では相互ロードされないので明示的に読む -->
2. 引数で渡された対象 issue ファイルを読む。
3. 完了検証（軽量ゲート）。通らなければ `done` にせず、理由を報告して差し戻す。
   - 「完了条件」節（旧テンプレートでは「検証」または「受け入れ条件」節）のチェックリストが全項目チェック済みか確認する（ボックスを埋めるのは実装した者の責務。detail の規則に従う）。未チェックがあれば保留し、その項目を挙げる。
   - 「未決」節（旧テンプレートでは「リスク・未解決」節）に項目が残っていれば保留し、その項目を挙げる。決まったものは「決めたこと」と設計方針へ、決まらないものは別 issue へ移すよう案内する。
   - 本文（現状・設計方針・実装メモ）と実リポジトリに明らかな食い違いが無いか確認する。あれば保留して指摘する。本文を実態に合わせるのは実装した者の責務である（detail の目的節に従う）。
   - 「完了条件」「検証」「受け入れ条件」のいずれの節も無い、または空の issue は、その旨を警告したうえで検証を通す。
   - 実装を伴う issue で多観点レビューが未実施と思われる場合は、coff-review-diff-code skill を案内する（案内はゲートの合否に含めない）。
4. 検証を通ったら、frontmatter と `status` の有無で分岐して `done` にする。
   - frontmatter があり `status` があれば、その値を `done` に書き換える。
   - frontmatter はあるが `status` が無ければ、`status: done` を frontmatter に追加する。
   - frontmatter が無ければ、ファイル先頭に `---` / `status: done` / `---` を挿入する（本文はそのまま後続させる）。
5. 本文（`#` 以降）は一切変更しない。
6. 更新後のパスと新しい `status` を報告する。

## 適用範囲

- 更新は `done` 方向のみ。取り消し（`done` → `open`）は手編集で行う。
