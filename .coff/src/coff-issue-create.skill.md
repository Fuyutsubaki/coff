## 手順

1. `.claude/skills/coff-detail-issue/SKILL.md` を読み込み、保存先・命名規則・テンプレート・品質基準を把握する。 <!-- skill は自動では相互ロードされないので明示的に読む -->
2. `issue/` ディレクトリが無ければ `mkdir -p issue` で作成する。
3. 問題空間だけを書く。ユーザーの要望から「タイトル / 背景・目的 / 現状」を言語化する。本文は japanese-tech-writing skill の規範に従って書く。
4. 問題の妥当性を吟味する（detail の4観点: 本当に解くべきか / すでに解決していないか / 問いの立て方は適切か / 別の捉え方はないか）。疑い・別の捉え方・棄却した枠は「リスク・未解決」に残す。深いコード調査はしない（問題の存在確認に最小限読むのは可）。問題の框（種別・目的・成功条件）が判定できないときだけ、grilling skill の規律で軽く聞く（一度に1問・推奨を添える）。聞きすぎない。
5. 解決空間（変更方針 / 対象範囲 / 実装詳細 / 受け入れ条件 / テスト方針）は書かない。「解決空間。polish で詰める」等のプレースホルダを置く。
6. 命名規則でファイル名を採番し、`issue/<name>.md` を作成する。
7. 作成したパスを報告する。続けて解を詰めるなら coff-issue-polish skill を案内する。

## 出口基準

- 問題が正しく立っていること。解は polish に委ねる。
