## 手順

1. `../coff-detail-issue/SKILL.md`（この SKILL.md の親ディレクトリ基準。cwd 基準ではない）を読み込み、保存先・命名規則・テンプレート・品質基準を把握する。 <!-- skill は自動では相互ロードされないので明示的に読む -->
2. 作成月のディレクトリを `mkdir -p "issue/$(date +%Y/%m)"` で用意する。
3. 問題空間だけを書く。ユーザーの要望から「タイトル / 要約 / 目的 / 現状」を言語化する。本文は coff-japanese-tech-writing skill の規範に従って書く。
4. 問題の妥当性を detail の4観点で吟味する。あわせて、独立に採否・完了を判断できる問題が複数含まれていないかを検査し、含むなら分割した起票を提案する（1 issue = 1 意図。detail の目的節に従う）。棄却した捉え方は目的に一文で残し、ユーザーの判断が要る疑いは「未決」に置く。深いコード調査はしない（問題の存在確認に最小限読むのは可）。問題の枠組み（種別・目的・成功条件）が判定できないときだけ軽く聞く。聞き方の規律: 一問ずつ聞く、各問に推奨案を添える、コードで分かることは聞かずに自分で調べる。全方位の質問攻めはせず、枠組みが定まればやめる。
5. 解決空間は書かない（detail の担当分けに従う）。
6. 命名規則でファイル名を採番し、`issue/<yyyy>/<mm>/<name>.md` を作成する。ファイル先頭に `status: open` の frontmatter を付ける（detail の状態仕様に従う）。
7. 作成したパスを報告する。続けて解を詰めるなら coff-issue-polish skill を案内する。

## 出口基準

- 問題が正しく立っていること。解は polish に委ねる。
