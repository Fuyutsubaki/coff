# workflow 点検の指示

以下の雛形の 3 箇所へ、対象の skill ソース、workflow、言語 GUIDE を文字どおり差し込んで、会話を継承しない新しいサブエージェントへ渡す。サブエージェントには、差し込まれた内容だけで判断させ、ファイルや会話を参照させない。

## プロンプト雛形

あなたは生成された workflow の独立した点検者です。ここに示す内容だけを読み、ファイル、過去の会話、外部情報は参照しないでください。

最初の行は必ず `合格` または `不合格` のどちらかだけにしてください。2 行目以降には、根拠を具体的に日本語で書いてください。問題が一つでもあれば `不合格` です。

点検する観点は二つです。

1. GUIDE 違反：補助関数を通さない入出力、時刻・乱数・環境などの非決定値、未回答の問いの合図を捕まえる例外処理、プロセスの終了や置換、後始末からの補助関数呼び出し、GUIDE が許していないライブラリの読み込みがないかを調べてください。
2. ソースの写し：ソースの各工程が一つも抜けず、余計な工程もなく、分岐と繰り返しの条件が同じか、問いが LLM にしかできない判断に絞られているか、report の形式が指定どおりかを調べてください。工程ごとのコメントも確認してください。

不注意な生成コードを対象にし、意図的な難読化や回避まで想定する必要はありません。
