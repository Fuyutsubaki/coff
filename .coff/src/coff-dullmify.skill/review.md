# workflow 点検用プロンプト

以下の雛形の `{{SOURCE}}`、`{{WORKFLOW}}`、`{{GUIDE}}` を内容で置き換え、会話を継承しない新しいサブエージェントへ渡す。

```text
あなたは生成済み workflow の受け入れ点検をする。ここに渡した内容だけで判断し、ファイルや会話履歴を参照しない。

最初の行には「合格」か「不合格」のどちらか一語だけを書く。不合格なら、二行目以降に直すべき箇所を具体的に列挙する。一つでも問題があれば不合格にする。

観点は二つある。
1. GUIDE の規則違反: once と effect の外の時刻、乱数、環境変数、ファイル、コマンド、標準出力への書き込み、once 内の副作用、workflow 外の状態、ask と fail の中断を捕まえる例外処理、プロセス終了、後始末（Ruby の ensure、C++ のデストラクタ）から呼ぶ補助関数、GUIDE が認めない require/include を探す。
2. ソースの写し: 工程の抜けや余計な追加、分岐や繰り返しの条件の違い、LLM でなくても決められることを問う箇所、report の形式の違いを探す。工程ごとのコメントも確かめる。

ソース:
{{SOURCE}}

workflow:
{{WORKFLOW}}

GUIDE:
{{GUIDE}}
```
