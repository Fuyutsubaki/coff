この SKILL.md のあるディレクトリを `<dir>` とする。同梱ファイルは `<dir>` からの相対パスで指す。

## 引数

`<source> -o <outdir> --lang <lang>`。3 つとも必須。欠けていれば、この形を示して止まる。

- `<source>`: 変換する skill のソース。frontmatter 付きの Markdown。frontmatter の値に `---` を含めない。 <!-- Claude Code は値の中の `---` を閉じ区切りと誤読し、後続の allowed-tools が落ちる（2026-09-25 に確認） -->
- `<outdir>`: 薄い skill を書き出すディレクトリ。中の `SKILL.md` と `scripts/` を置き換える。ほかのファイルには触れない。
- `<lang>`: `<dir>/langs/` にあるディレクトリ名。`<dir>/langs/<lang>/GUIDE.md` がなければ、`<dir>/langs/` の一覧を示して止まる。

## 手順

1. `<source>` と `<dir>/langs/<lang>/GUIDE.md` を読む。
2. workflow を書く。書くのは workflow 本体だけ。ランタイムと起動スクリプトは `assemble.sh` が同梱する。
   - ソースの手順の制御（分岐、繰り返し、ファイルとコマンドの扱い、答えの検査）はすべてプログラムに書く。LLM にしかできない判断（文章の解釈、抽出、分類、ユーザーへの確認）だけを問い `ask` にする。
   - 問いの文面に、何をどう答えるかを書く。答えに形式を求めるときは workflow で検査し、壊れていたら理由を添えて問い直す。問い直しの上限は workflow で決める。
   - ファイルの書き換えやコマンドの実行を問いの文面で LLM にさせない。副作用は補助関数で起こす。答えるのにツールが要る問い（ユーザーへの確認、ファイルの参照）は、文面でそれを指示してよい。
   - 外界とのやり取りは GUIDE の補助関数だけを通す。補助関数を通さない入出力はバグ。
   - ソースの工程（番号付きの手順の 1 項目。手順がなければ段落）ごとに、節の見出しと工程の番号をソースの言語でコメントする。
   - 報告は、ソースが定める形の文字列で返す。
3. workflow を、ファイルを書くツールで `<outdir>/scripts/<GUIDE が定めるファイル名>` に書く。Bash の heredoc で渡さない。 <!-- Claude Code の Bash ツールは `{`、引用符、`}` をこの順で含むコマンドを静的に拒否する。heredoc の本文も対象で、C++ の関数本体は必ず当たる（2026-09-25 に確認） -->
4. `assemble.sh` で検査して書き出す。`<dir>` の絶対パスで、単独のコマンドとして呼び、3 で書いたファイルのパスを渡す。

   ```
   sh <dir>/assemble.sh <lang> <source> <outdir> <outdir>/scripts/<ファイル名>
   ```

   検査に通らなければ、`assemble.sh` は理由を出し、3 で書いたファイルも消して、`<outdir>` に何も残さない。理由を読んで workflow を直し、3 から繰り返す。生成と検査は合わせて 3 回まで。3 回目も通らなければ、最後の理由を添えて失敗を報告して止まる。検査を回避しない。別の手段でコンパイラや検査を呼ばず、拒否された API を同じ働きの別の書き方に変えるだけの修正もしない。
5. `assemble.sh` の出力（書き出したファイルの一覧）を報告する。
