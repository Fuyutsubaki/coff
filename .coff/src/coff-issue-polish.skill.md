## 手順

1. `.claude/skills/coff-detail-issue/SKILL.md` を読み込み、テンプレートと品質基準を把握する。 <!-- skill は自動では相互ロードされないので明示的に読む -->
2. 対象 issue を読み、テンプレートと基準に照合して欠けているセクションと曖昧点を洗い出す。
3. コード調査: 関連ファイル、既存実装、依存を実際に読み、「現状 / 対象範囲 / 実装詳細」を事実に基づいて埋める。
4. 前提検証: 記載されている前提が現在のコードと矛盾しないか確認する。矛盾は修正し、要判断点は「リスク・未解決」に移す。
5. （必要なら）試験実装。実現可能性が不確かな箇所は小さく試して確かめる。安全手順:
   - 着手前に `git stash` で作業ツリーを退避し、確認後 `git stash pop` か破棄で戻す。
   - 別プロセスで実行する場合は codex-delegate skill に委譲し、結果だけ回収する。
   - いずれも試験実装の成果物は、issue ファイルへの追記以外はコミットに含めない。
6. 多視点の自己レビューを数回行う: 実装者が迷わないか / 受け入れ条件は検証可能か / テスト方針は十分か / 抜け漏れはないか / リスクを網羅できているか。
7. issue ファイルを上書き更新する。日本語の文章は japanese-tech-writing skill の規範に従い、論証の筋は argument-gap-edit skill で点検する。適用した変更点と残課題を報告する。

## 仕上がり基準

- 実装者が issue だけで着手できること。
