## 手順

1. `.claude/skills/coff-detail-issue/SKILL.md` を読み込み、テンプレートと品質基準を把握する。 <!-- skill は自動では相互ロードされないので明示的に読む -->
2. 対象 issue を読み、まず問題空間を点検する。問題の妥当性4観点を満たし問題が正しく立っているか確かめ、崩れていれば「目的 / 現状」を立て直す（問題空間への差し戻し）。あわせて、独立に採否・完了を判断できる問題が複数含まれていないかを検査し、含まれていれば分割を提案する（1 issue = 1 意図。detail の目的節に従う）。
3. コード調査: 関連ファイル、既存実装、依存、関連 skill・ドキュメント・関連 issue を実際に読み、「現状 / 実装詳細」を事実に基づいて埋める。外部資料の調査結果は「調査記録」に出典つきで書く。
4. 前提検証をチェックリストで行う: 記載の前提が現在のコードと矛盾しないか / 参照するファイルパスが実在するか。矛盾は修正し、ユーザーの判断が要る点は「未決」に移す。
5. 論点の仕分け。詰める過程で出る論点を「コードで答えが出る」「ユーザーの判断が要る」に分ける。前者は手順3-4で自分で調べて解決し、人間には聞かない。後者だけ確定前に聞く。聞くときの規律: 一問ずつ聞く、各問に推奨案を添える、コードで分かることは聞かずに自分で調べる。問答の出口は「汎用的な合意」ではなく「この issue が単体で実装可能になること」に置く。決まった論点は「未決」から消し、detail の規則に従って「決めたこと」か設計方針に書く。決め打ちで仕様化しない。
6. 解決空間（設計方針 / 完了条件 / 実装メモ）を detail のテンプレート規則に従って書く。設計方針には採用案とその理由、検討した代替案と却下理由、対象外を集約し、他の節に散らさない。実装メモは detail の「残す / 溜めない」の基準に従う。
7. （必要なら）試験実装。実現可能性が不確かな箇所は小さく試して確かめる。安全手順:
   - 着手前に `git stash` で作業ツリーを退避し、確認後 `git stash pop` か破棄で戻す。
   - 別プロセスで実行する場合は codex-delegate skill に委譲し、結果だけ回収する。
   - いずれも試験実装の成果物は、issue ファイルへの追記以外はコミットに含めない。
8. 自己レビュー。detail のテンプレート規則と polish の出口基準に照らして読み直す。加えて次を見る。
   - ユーザーに聞くべき論点を黙って決め打ちしていないか。
   - 却下理由が実際にその案への反論になっているか（案の前提の取り違えや、案と無関係な一般論は書き直すか削る）。
   - 後で読む人に無用な、またはすぐ古くなる情報を書いていないか。
9. タイトル直下の要約（2、3 行: 何をなぜ）を必要なら更新し、issue ファイルを上書き更新する。旧テンプレートの issue（`## 要約` `## 人間が決めた判断` などがある）なら、新テンプレートの構成に書き換える。先頭の frontmatter（`status` を含む）は保存し、`status` の値は変えない（完了判断は coff-issue-done の責務）。日本語の文章は coff-japanese-tech-writing skill の規範に従い、論証の筋は coff-argument-gap-edit skill で点検する。
10. 実装者シミュレーションを行う。新鮮なコンテキストのサブエージェント（会話を継承する fork ではない）を起動し、更新した issue ファイルだけを読ませて次の4点を返させる: 実装計画の骨子 / 着手を妨げる点 / 曖昧な点 / 完了条件の各条件が実行可能か。polish セッションの会話文脈は渡さない（リポジトリの読み取りは許す。実装者もリポジトリは読める前提）。指摘の解消は原則「実装メモ」に書き、折り目より上は完了条件・設計方針・決めたこと・未決が実際に変わるときだけ動かす。issue を変更したときだけ上書きして再実行する。上限は2周とし、解消しない点のうちユーザーの判断が要るものは、手順 5 の規律でその場で聞いて確定させる（未決に残して終えない）。的外れな指摘は採らずに捨て、指摘への防御で issue を膨らませない。 <!-- 代替手段は codex-delegate。ネイティブのサブエージェントを既定にするのは plugin 依存を避けるため（issue/2026/07/1518-polish-implementer-sim.md の判断） -->
11. 適用した変更点と残課題を報告する。

## 仕上がり基準

- detail の polish の出口基準を満たすこと。
