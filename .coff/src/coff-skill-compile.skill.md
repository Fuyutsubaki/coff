## 入出力

- 入力 glob: `.coff/src/*.skill.md`
- ソース `.coff/src/<name>.skill.md` → 出力 `.claude/skills/<name>/SKILL.md`
- `<name>` はソースのファイル名から `.skill.md` を取り除いたもの。

## オプション

引数で以下を受け付ける（任意の順序、組み合わせ可）:

- `--lint-only`: lint 段階で停止し、コンパイルしない。許可ゲートも省略。
- `--force`: md5 一致によるスキップを無視し、対象を全て処理する。
- `<path|name> [<path|name> ...]`: 指定したソースのみ処理する。`.coff/src/foo.skill.md` のフルパスでも、`foo` だけでも、`foo.skill.md` だけでも受け付ける。指定なしなら `.coff/src/*.skill.md` 全件。

例:
- `/coff-skill-compile --lint-only` — 全件 lint のみ（md5 一致のものはスキップ）。
- `/coff-skill-compile --force` — md5 を無視して全件再ビルド。
- `/coff-skill-compile foo` — foo だけ lint+compile。

## 1. ビルド対象の特定

```bash
src=.coff/src/<name>.skill.md
dst=.claude/skills/<name>/SKILL.md
src_md5=$(md5sum "$src" | cut -d' ' -f1)
dst_md5=$(tail -n 1 "$dst" 2>/dev/null | grep -oP '"md5":"\K[a-f0-9]{32}')
[ "$src_md5" = "$dst_md5" ] && echo skip || echo build
```

空ソースはハードエラー — レポートして次へ。

## 2. Lint

ビルド対象の各ソースについて、以下を検出する。

| 候補 | 種別 | 適用方法 | デフォルト |
|---|---|---|---|
| WHY / 設計動機 / 全体像説明 | safe | `<!-- -->` で囲う | 承認 ON |
| 対人向けメタ指示 (「手で編集するな」等) | safe | `<!-- -->` で囲う | 承認 ON |
| 同義反復・スタイル違いで言い直してる文（特に "肯定形 X。否定形 X。" のような positive+negative ペア） | safe | 後続文を `<!-- -->` で囲う | 承認 ON |
| 対偶・Yes/No 並列の冗長明記（条件文 + 「Yes→A / No→B」の列挙、または「X なら Y。X でなければ Y しない」型） | safe | 列挙側を `<!-- -->` で囲う | 承認 ON |
| WHAT の重複 (frontmatter description ⇄ 冒頭段落 等) | lossy | 削除/統合 | 承認 OFF |
| H1 見出し ⇄ frontmatter `name` の重複 | lossy | 削除 | 承認 OFF |
| frontmatter description が冗長 | lossy | 短縮 | 承認 OFF |
| 構造的重複（高レベル要約セクション ⇄ 詳細セクション群が同じ手順を 2 度語る） | lossy | 要約側を削除 | 承認 OFF |
| 冗長な例示（汎化ルールの直後に網羅的な組み合わせ例。`combinable` などと明言済みなのに全組み合わせを列挙） | lossy | 代表例 2-3 件まで圧縮 | 承認 OFF |

検出指針: その文を**生成物から消した**ときに、実行 LLM が手順を完遂できるか？
<!--
- 完遂できる → 候補に挙げる。
- 完遂できない → 触らない。
-->

スコープ除外:
- 既に `<!-- -->` 内にあるもの。
- フロントマター内、コードブロック内、インラインコードスパン内。

ただし frontmatter `description` だけは別途チェックする。WHAT とユーザー HOW（引数・呼び出し方）以外（内部手順・実装詳細・WHY）が含まれていたら lossy 候補に挙げ、削るべき箇所を引用しつつ短縮案を提示する。

## 3. 対話的承認

候補が 0 件ならこのステップを飛ばす。

候補が見つかったら、`AskUserQuestion` の `multiSelect=true` で一括提示する。

- ファイルごとにグループ化し、候補ごとに「該当行・引用・種別 (`safe` / `lossy`)・推奨・適用後の見え方」をラベルに含める。
- 推奨はラベルの先頭タグで明示する。例: `[safe・推奨]`、`[lossy]`。<!-- AskUserQuestion は事前選択をサポートしないため、推奨はラベル文字列で伝える。 -->
- ユーザーが選んだものだけ source に書き戻す。

書き戻し方:
- safe (コメント化): 該当範囲を `<!-- ... -->` で囲う。元の文言は変えない。
- lossy: 提示した書き換え案で置換、または該当行を削除。

候補が多すぎてバッチに収まらない場合は、ファイル単位 → セクション単位で分割して順次提示。

## 4. コンパイル許可ゲート

lint で 1 件でも候補が提示された（適用有無問わず）場合、コンパイル前に明示確認:

> "Lint 完了。N 件適用、M 件却下。コンパイルしますか？"

却下なら中止。承認なら 5 へ。

<!-- 候補が 0 件だった場合はゲートを省略してそのまま 5 へ。 -->

## 5. コンパイル

lint で書き換えたファイルは §1 で取った `src_md5` が古くなっているので、フッタ書き込み前に再計算する。各ビルド対象について:

a. **日本語→英語に翻訳する。** 散文・見出し・リスト項目・フロントマターの `description` 値を簡潔な英語に書き直す。<!-- 英語は実行時に日本語より少ないトークンで処理できる。それがそもそもの目的。 -->

   翻訳してはいけない（バイト単位で保持）:
   - モデルが照合対象として使う、または逐語的に出力すべき引用符付きリテラル。例: `ファイル名が "注文" から始まるファイル` の `"注文"` は日本語のまま。周囲の文章だけを訳す → `files whose name starts with "注文"`。
   - コード識別子、関数名、ファイルパス、CLI フラグ、正規表現、コマンド引数。
   - フェンスコードブロック（` ``` … ``` `）およびインラインコードスパンの中身。
   - フロントマターのキー。フロントマターの `name` 値。識別子として機能するその他のフロントマター値。
   - 固有名詞: 製品名、プロジェクト名、人名。
   - UI 文字列、エラーメッセージ、その他ユーザー/モデルが逐語的に再現すべき文字列。

   迷ったら原文のまま残す。

b. **本文中の HTML/markdown コメントを除去する。** 本文中の `<!-- ... -->` ブロックを全て除去する。フェンスコードブロック内およびインラインコードスパン内のコメントは除去しない。フロントマターブロックには触れない。

c. **フロントマターの構造を保持する。** 先頭の `---` … `---` ブロックは出力でも有効な YAML フロントマターであり続けること。ソースにフロントマターが無ければエラーで中断。

d. **書き出してフッタを付与する。** フッタは出力の最終行、本文の後、コードブロックの外。

   ```bash
   mkdir -p "$(dirname "$dst")"
   printf '%s\n<!--{"src":"%s","md5":"%s"} -->\n' "$body" "$src" "$src_md5" > "$dst"
   ```

## 6. レポート

各ソースについて以下のいずれかで報告:
- `compiled` （lint で N 件適用していれば併記）
- `linted (N applied, M rejected)` — `--lint-only` のとき、または許可ゲートで却下されたとき
- `failed: <reason>`

スキップ済みは出さない。lint 候補が 0 件で `--lint-only` のときも何も出さない。

## ルール

- ソースの破壊的変更は lint 承認分のみ。<!-- 承認外で `.coff/src/` を書き換えない。 -->
- フロントマターの `name` 値、生成物パスを構成する識別子は lint でも触らない。
- lint も compile もアトミック: 途中失敗で部分書き込みを残さない。
