# dullmify に、変換の前にソースの問題を指摘して直す lint モードを加える

dullmify の lint モードは、skill のソースのうち、曖昧で問題になりそうな部分と、LLM への問いが細切れになりすぎて逆に高くつく部分を指摘し、ユーザーの許可を得て直す。
これらを変換の前に取り除き、dullmify の狙う制御の揺れの防止とトークンの削減が、変換後に崩れないようにする。

## 目的

dullmify は、skill のソースの散文から制御を読み取ってプログラムにする（issue/2026/09/2200-add-dullmify.md）。
ソースが制御を決めきれていないと、変換するたびに違うプログラムができる。
実行時の揺れを防ぐはずが、揺れが変換時に移るだけになる。
また、LLM への問いが細切れになる書き方だと、問いのたびにプログラムの実行と LLM の応答の往復が要り、LLM に手順を読ませるより高くつく。
本 issue の目的は、こうした箇所を変換の前に指摘し、許可を得てソースを直すことである。

## 現状

- dullmify 本体はまだない（issue/2026/09/2200-add-dullmify.md）。
- coff-compile には、許可を得てソースを直す lint の段が既にある（`.coff/src/coff-compile.skill.md` の「2. Lint」「3. 対話による承認」）。生成物から消しても実行 LLM が手順を完遂できる文を候補に挙げ、`AskUserQuestion` の複数選択で承認された候補だけをソースに反映する。

## 決めたこと

- lint は dullmify のオプションの一つにする

## 未決

- 指摘の対象は上の 2 つで足りるか。細切れの逆で、手順をまるごと LLM に任せる問いや、LLM にファイルを書かせる問いを加える案がある。どちらも制御と権限を LLM に戻してしまう。
- 検出のしかた。依頼者の案は、まず通常のレビューをし、次に並行に複数回変換して結果が変わる箇所を探すもの。
