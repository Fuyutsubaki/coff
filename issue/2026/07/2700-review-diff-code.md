# 完了前の多観点レビュー skill を追加する

## 要約

done 前に手打ちで繰り返されてきた観点別レビューを skill 化する。
coff-review-diff-code が現在のブランチの差分を固定 6 観点の subagent レビューにかけ、指摘を集約して報告する。
coff-issue-done には、ゲートの合否に関わらない一言の案内を足す。

## 背景・目的

実装を仕上げて issue を done にする前に、観点別の subagent レビュー（一般的なレビュー観点、YAGNI、仕様が無意味に複雑でないか、issue が複雑すぎないか）を手打ちのプロンプトで依頼する運用が、4 セッション以上繰り返されている。
毎回同型のプロンプトを打つのは往復の無駄であり、観点の抜けも起きる。
この運用を skill として固定し、完了前に呼べる入口にしたい。

## 現状

- coff-issue-done（`.coff/src/coff-issue-done.skill.md`）は軽量ゲート（検証ボックスの充足と本文・実リポジトリの整合確認）だけで、実装物のレビュー工程を含まない。
- coff-issue-polish の実装者シミュレーション（手順 10）は「issue 文書が単体で実装可能か」の点検であり、実装物のレビューではない。
- polish 手順 10 のコメントに「ネイティブのサブエージェントを既定にするのは plugin 依存を避けるため」という判断が記録されている（`issue/2026/07/1518-polish-implementer-sim.md`）。新 skill もこれと整合させる必要がある。
- 別プロセスでの実行手段としては codex-delegate skill（`.coff/src/codex-delegate.skill.md`）が既にあり、ブリーフを渡して委譲する形をとる。

## 変更方針

skill `coff-review-diff-code` を新設し、汎用ライブラリとして配布する（`coff-dist: true`）。
レビュー対象は現在のブランチの差分（基底ブランチとの差分と、未コミットの変更）とする。
観点は次の 6 つに固定し、観点ごとに subagent を並列に立ち上げ、指摘を集約して報告する。修正はせず、指摘の採否は呼び出し元に委ねる。

1. 一般的なレビュー観点（正しさ、既存規約との整合、退行）
2. YAGNI（未使用の拡張点、上位で担保済みの再チェック、起き得ない保険）
3. 仕様は無意味に複雑ではないか
4. issue は複雑すぎないか（差分に含まれる issue が変更の実体と釣り合っているか）
5. 同種アンチパターンの横展開漏れ（差分で直した問題と同種のものが差分の外に残っていないか）
6. 入口 artifact の実在と薄さ（依頼された入口が作られているか、仕様の写しで肥っていないか）

実行系はネイティブの subagent を既定とし、codex-delegate が導入されていれば別プロセスの代替として委譲できる（codex-delegate は配布対象外なので、導入先に常にある前提では書かない）。codex-delegate を既定にする案は、plugin 依存を避ける既存判断（現状の節を参照）と矛盾するため採らない。
観点を引数で追加できるようにする案は、4 セッション以上の実運用が固定観点のまま繰り返されており可変にする必要が出ていないため、今回は入れない。
coff-issue-done への統合（レビューをゲート化する）案は、done は軽量ゲートという設計を崩すため採らない。かわりに、実装を伴う issue でレビュー未実施と思われる場合に coff-review-diff-code を案内する一文を done の手順に足す。案内はゲートの合否に含めない。

## 実装詳細

- `.coff/src/coff-review-diff-code.skill.md` を新規作成する。frontmatter は `name` / `description` / `license: MIT` / `coff-dist: true`。手順の骨子:
  1. レビュー対象の確定。基底ブランチ（`origin/HEAD` が指す既定ブランチ。無ければ master / main の存在する方）との差分と、未コミットの変更を集める。差分が空ならその旨を報告して終える。
  2. 観点ごとに subagent を並列起動する。subagent は読み取り専用で動かし、ファイルの修正はさせない。各 subagent には基底ブランチ名と担当観点を渡し、差分は subagent 自身に取得させる（作業ツリーと基底の diff を取り、未追跡ファイルは直接読ませる。大きい差分を本文に埋め込まない）。観点外の指摘はさせない。観点 4 と 6 は判定材料を差分内の issue ファイルに求め、無ければ「対象なし」と返す。観点 5 だけは差分の外も見るが、探索は差分で直した問題と同種のパターンの検索に限る。
  3. 指摘を集約して報告する。同一箇所・同一趣旨の指摘は一つにまとめ、正しさに関わる指摘を先に並べる。
- `.coff/src/coff-issue-done.skill.md` の手順 3 に、非ブロッキングの案内（実装を伴う issue でレビュー未実施と思われる場合は coff-review-diff-code を案内する。合否には含めない）を一文追加する。
- `.coff/src/coff-init.skill.md` の一括導入の対象リストに coff-review-diff-code を追記する（配布 skill は coff-init 経由で導入先に伝播するため。初回実装で漏れ、本 skill 自身の初回レビューが検出した）。
- `/compile` で各ソースをビルドし、dist ミラー `skills/` を同期する。

## 人間が決めた判断

- セッション振り返り（gist）の候補から本件を採用する判断は依頼者による（2026-07-26）。
- レビューの実行系はネイティブの subagent を既定とし、codex-delegate は代替とする（依頼者が「native subagent 既定」の案を選択。2026-07-26）。
- 振り返りの A-1（ユーザ入口の artifact を作らず下回りだけ作る、または入口に仕様を写して肥らせる）は、常時規範として配布せず、この skill の観点で拾う（2026-07-27）。
- 観点は 6 観点（4 観点 + 横展開漏れ + 入口 artifact）で固定する（2026-07-27）。
- 名前は coff-review-diff-code とし、今のブランチを対象に review をするものとする（2026-07-27）。
- coff-issue-done には一言の案内を足す（軽量ゲートの設計は維持。2026-07-27）。

## リスク・未解決

- 「レビュー未実施と思われる場合」を done が機械的に判定する手段はない。案内は会話文脈からの推定でよく、外れても実施を強制しないので実害は小さい。
