# issue 完了時の検証とリポジトリ整備をまとめて行う

## 背景・目的  〔問題 / create〕
issue の運用まわりで溜まっていた3つの整備を一括で扱う。相互に独立だが、いずれも「issue とリポジトリを事実に整合した状態に保つ」点で通底する。

- **A. done 時の検証**: coff の issue は実装の指示書であると同時に、設計判断の長期記憶でもある。完了マーク（`status: done`）は「内容は達成され、記録として信頼できる」という宣言に等しい。だが現状の done はフラグを書き換えるだけで宣言を裏づける検証をせず、「未完了なのに done」「記録が現状と矛盾したまま done」を検出できない。done を検証の門にしたい。
- **B. issue ディレクトリの階層化**: issue が `issue/` 直下にフラットに溜まり、件数増加で見通しが悪い。年月の階層で時系列の見通しを良くしたい。
- **C. 不要物の削除**: 役目を終えた空ファイルや置き去りの成果物を洗い出して削除し、目的のファイルだけの状態を保ちたい（直近でも空の `example.skill.md` を削除済み。コミット `f327a69`）。

## 現状  〔問題 / create〕
### A. done 時の検証
`.coff/src/coff-issue-done.skill.md`（成果物 `.claude/skills/coff-issue-done/SKILL.md`）は、状態仕様の把握 → 対象 issue を読む → `status` を `done` に書き換える → 本文は一切変えない、で完結する。検証の段が無く、受け入れ条件（polish が埋めるチェックリスト）の充足も、issue 本文と実リポジトリの整合も確認しない。

### B. ディレクトリ階層化
保存先と命名規則は coff-detail-issue が唯一の参照元として定義する（`issue/` 直下、`yymmddHH-<slug>.md`）。create がこの規則で採番し、done・polish はパスを変えずに更新する。`26063023-issue-done-status.md` は「ファイルを動かさない＝ issue 間のパス相互参照が壊れない」を done 設計の根拠にしており、実際に既存 issue の `## 参考` は相対パスで相互参照している。一覧は `grep 'status: done' issue/*.md` 前提。

### C. 不要物
現時点でリポジトリは概ね整理済みで、明白なゴミは残っていない。`.coff/src/` の各ソースと `.claude/` の成果物は1対1で対応し孤立成果物は無い。`.coff/tmp/` は空ディレクトリで、git 追跡外かつどこからも参照されていない（stray なローカルディレクトリ）。`.claude/settings.local.json` は git 管理外なのでリポジトリの不要物ではない。

## 変更方針  〔解 / polish〕
3件は独立した変更として扱う。skill の挙動変更はすべて `.coff/src/` を編集し、`/coff-compile` で `.claude/` へ反映する（`.claude/` 成果物は手編集しない）。

### A. done を軽量ゲート化
coff-issue-done に、`status` を `done` にする前段の検証を挿す。

- 受け入れ条件チェックリストが全て満たされているか確認する。未達があれば done を保留し、未達項目を報告して差し戻す。
- 本文（現状・変更方針・実装詳細）と実リポジトリの明らかな食い違いに気づいたら指摘し、done を保留する。本文の自動修正はしない（done の「本文を変えない」設計を維持し、矛盾の解消は人が本文修正かリスク移送かを判断する）。
- 受け入れ条件が空／不在の issue は、警告のうえ done を通す（`status` 既定と同じ後方互換）。

却下案: **整合まで踏み込み done 時に本文を修正**（26063023 の「本文を変えない」設計と衝突。AI の突き合わせ精度リスク）／**受け入れ条件の確認のみ**（現状との食い違い検出を失う。ユーザーが軽量ゲートを選択）。

### B. 保存先を年月階層へ全件移行
保存先を `issue/<yyyy>/<mm>/` に変え、既存 issue を全件移して相互参照を一括更新する。

- 年月は作成時の日付から `date +%Y/%m`。既存 issue は接頭辞 `yymmdd` から年月を割り出して振り分ける（`26xxxx` → `2026/06|07`）。
- ファイル名の接頭辞から重複する年月を外し、`<ddHH>-<slug>.md` にする。年月はディレクトリが表すので接頭辞から落とし、日・時だけを残す（月内のソートと一意性を担う）。
- 移行と `## 参考` の相対参照の張り替えを同一コミットで行う。相対リンクは原子的に更新されるので壊れない。
- 一覧は再帰 glob に変える（例 `grep -rl 'status: done' issue`）。

却下案: **新規だけ階層化**（新旧混在で一貫性が下がる）／**見送り**（要望を満たさない）／**年/月/日粒度**（日ごとに1件だけのディレクトリが乱立）。全件移行を1コミットで行えば、26063023 の「参照が壊れない」という意図とは両立する。

### C. 単発掃除
stray な空ディレクトリ `.coff/tmp/` を除去し、追跡下に空ファイル・孤立成果物が残っていないことを確認する。継続的な検出の仕組みは作らない（対象が希薄なため）。

## 対象範囲・対象ファイル  〔解 / polish〕
- **A**: `.coff/src/coff-issue-done.skill.md`（検証段の追加）。検証観点を共通化するなら `.coff/src/coff-detail-issue.skill.md` に最小限。
- **B**: `.coff/src/coff-detail-issue.skill.md`（保存先・命名の bash 例・一覧 glob）、`.coff/src/coff-issue-create.skill.md`（`mkdir` と保存パス）、既存 issue 5件の移動と各 `## 参考` の参照更新。
- **C**: `.coff/tmp/` の除去。
- skill ソースの変更は `/coff-compile` で `.claude/` へ反映する。

## 実装詳細  〔解 / polish〕
- **A**: done 手順の「`status` を `done` に書き換える」直前に検証段を置く。受け入れ条件節の未チェック項目を検出／本文と実状態の食い違いを確認／どちらか引っかかれば保留して報告、通れば従来どおり `status` を更新。手順の粒度は coff-detail-issue の品質基準に委ね、丸写しはしない。
- **B**: 保存先規則を `issue/<yyyy>/<mm>/<ddHH>-<slug>.md` に更新。detail の採番例を `dir="issue/$(date +%Y/%m)"; ts=$(date +%d%H); mkdir -p "$dir"` 相当にし、create の `mkdir -p issue` と保存パスを同ディレクトリへ差し替える。既存移行の対応（ディレクトリ移動と同時に接頭辞から年月を落とす）:
  - `2026/06/`: `2803-import-tech-write-ja.md`、`2822-improve-issue-workflow.md`、`3023-issue-done-status.md`
  - `2026/07/`: `0200-polish-write-restraint.md`、`0222-issue-upkeep-and-cleanup.md`（本 issue 自身も移動・改名する）

  参照の張り替え箇所は `grep -rn 'issue/[0-9]' issue` で洗い出す（ファイル名も変わるので、参照は新パス＋新ファイル名へ更新する）。
- **C**: `.coff/tmp/` は未追跡なので `rmdir .coff/tmp` はローカル整理に留まりコミット差分を生まない。追跡下に空／孤立ファイルが無いことを `git ls-files` とソース↔成果物対応の目視で確認する。
