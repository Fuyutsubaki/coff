# polish の出口に実装者シミュレーションを追加する

## 背景・目的  〔問題 / create〕
polish の出口基準は「実装者が issue だけで着手できること」だが、その充足は polish 自身の自己レビューでしか確かめられない。
書いた本人と同じコンテキストが読み直す構造なので、盲点（暗黙の前提、書かれていない手順）はそのまま残る。
出口基準を直接テストする手段として、新鮮なコンテキストのエージェントに issue だけを読ませ、実装計画と不明点と検証手段を返させ、詰まった箇所を polish に還流する「実装者シミュレーション」を polish の出口に加える。

## 現状  〔問題 / create〕
- coff-issue-polish の手順8は8項目の自己レビューで、別コンテキストによる検証はない。
- Claude Code にはネイティブのサブエージェント機構があり、polish の会話文脈を共有しない新規コンテキストで実行できる。
- codex-delegate skill で別プロセスへの委譲も可能だが、polish には組み込まれていない。
- 出口基準の不充足が実害になった例（issue から実装して詰まった実例）は、まだリポジトリにない。本 issue は予防的な提案である。

## 変更方針  〔解 / polish〕
polish の自己レビュー（手順8）の後、ファイル書き出しの前に実装者シミュレーションの段を追加する。

- 毎 polish で実行する。
- 手段は新鮮なコンテキストのサブエージェントとする。issue 本文だけを入力し、「この issue だけを頼りに実装計画を立て、着手できない点、曖昧な点、検証できない条件を列挙せよ」と指示する。リポジトリの読み取りは許す（実装者もリポジトリは読める前提）。polish セッションの会話文脈は渡さない。
- 指摘があれば polish が解消して再実行する。上限は2周とし、解消しない点は「リスク・未解決」に明記したうえで完了する。
- 的外れな指摘は採らずに捨ててよい。指摘への防御で issue を膨らませない。

検討した代替案と却下理由。

- codex-delegate での実行を既定にする。実行はできるが plugin への依存が増える。coff は汎用ツールなので、ネイティブのサブエージェントを既定とし、codex は代替手段にとどめる。
- ユーザー指示時のみ実行する。出口ゲートとして機能するのは常時実行のときだけであり、ユーザーが毎回実行を選んだ。
- polish が issue の重さで実行を判断する。判定が主観になり、ゲートが骨抜きになるため却下。

## リスク・未解決  〔横断〕
